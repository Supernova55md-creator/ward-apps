# 病棟アプリ（ward-apps）

自分の端末でオフライン利用するための病棟アプリ置き場です。GitHub Pages で公開し、各端末のホーム画面に追加して使います。

## 初回の公開手順（Mac のブラウザで約10分）

1. GitHub にログインし、右上「＋」→「New repository」
   - Repository name：`ward-apps`（推測されにくい名前でも可）
   - **Public** を選ぶ（無料プランの GitHub Pages は公開リポジトリが必要）
   - 「Create repository」
2. 作成直後の画面の「uploading an existing file」をクリック
3. この zip を展開した **ward-apps フォルダの中身**（`index.html` と `dm` フォルダ）をドラッグ＆ドロップ →「Commit changes」
4. リポジトリの「Settings」→ 左メニュー「Pages」
   - Source：「Deploy from a branch」
   - Branch：`main` ／ `/(root)` →「Save」
5. 1〜2分待つと `https://<GitHubのユーザー名>.github.io/ward-apps/` で開けるようになる

## 端末への追加

- **iPhone / iPad（Safari）**：`…/ward-apps/dm/` を開く → 共有ボタン →「ホーム画面に追加」
- **Galaxy（Chrome）**：同じURLを開く → 右上メニュー →「ホーム画面に追加」（または「アプリをインストール」）
- 追加後に一度アイコンから開けば、以後は通信なしで動きます。

## 更新するとき

1. 新しい `dm/index.html` を GitHub で上書きアップロード
2. `dm/sw.js` の `VERSION` を変える（例：`dm-2026-11-08a` → `dm-2026-11-15a`）
3. 端末でアプリを1回開く（通信あり）→ 「新しい版を取り込みました」と出たら、次に開いたときから新しい版

## 注意

- 入力データは各端末のアプリ内（ブラウザ領域）だけに保存され、GitHub には送られません。iPhone ではホーム画面のアプリと Safari のデータは別です。
- 公開リポジトリなので、URL を知っている人は誰でも画面を開けます（検索エンジンには載らない設定）。自分用の利用にとどめ、他の人に配る場合は医療機器プログラム該当性の確認が必要です。
- 写真から読み込む機能は claude.ai 上の版だけで動き、この版には表示されません。
- 入口の index.html は複数の作業から同時に上書きすると行が消えることがあります。更新前に最新版を取得し、アップロード後に全アプリの行が残っているか確認してください。
- MDS-UPDRS 評価ツール（updrs/）には判定基準の本文を含めていません。判定基準は手元の JSON を各端末のアプリ内で読み込み、その端末にだけ保存します。JSON はこのリポジトリに置かないでください。

## 1つのPWAに統合（2026-11-08〜）
同じドメイン（supernova55md-creator.github.io）に複数のPWAを置くと、Android の Chrome で2つ目以降が「すでにインストールされています」→「アプリを開けませんでした」となるため、ward-apps 全体を1つのPWA「病棟アプリ」にまとめた。

- インストールするのは入口（/ward-apps/）の1つだけ。manifest.webmanifest・sw.js・アイコンは直下にある。
- Android：入口を開いて Chrome のメニュー →「アプリをインストール」。アイコン長押しで各アプリへのショートカット（manifest の shortcuts）。
- iPhone：各アプリを開いて 共有 →「ホーム画面に追加」で、アプリごとのアイコンも作れる（各アプリの apple-touch-icon を使う）。
- 各アプリの index.html には manifest へのリンクを置かない。service worker は直下の ../sw.js を scope "../" で登録する。
- 各アプリの sw.js は廃止用（古い登録とキャッシュを消して自分を解除するだけ）。消さずに残しておく。

### 新しいアプリを足すとき
1. <slug>/ に index.html とアイコン3つ（icon-192.png・icon-512.png・apple-touch-icon.png）を置く。manifest へのリンクは入れない。service worker は register("../sw.js",{scope:"../"}) で登録する。
2. 直下の index.html の <ul> に1行追加。
3. 直下の manifest.webmanifest の shortcuts に1件追加。
4. 直下の sw.js の APPS に slug を足し、VERSION を変える。
5. index.html の </body> 直前に <script src="../share.js" defer></script> を置く（右上にQRボタンが出る）。

### アプリを更新したとき
- 直下の sw.js の VERSION を必ず変える（各アプリの sw.js ではない）。
- 入口の index.html・sw.js・manifest は1つの会話でまとめて更新する（複数の会話で同時に上書きすると行が消える）。

## QCストーリー支援（qc/）について
- 院内QC活動のメンバーに配る想定のツール。診療に使うものではないので医療機器プログラムには当たらない。
- 入力はその端末の中だけに保存。メンバー間の受け渡しは「概要」の「このプロジェクトを書き出す」（.json）→「ファイルを読み込む」で行う。
- 患者の氏名・IDなど個人が特定できる情報は入力しない（画面にも注意書きあり）。
- 「入力クリア」は今開いている作業中のプロジェクトだけを空にする。保存済みプロジェクトの一覧（qc-story-lib-v1）は残る。

## 院内内線（ext/）について
- **このリポジトリに内線データの平文（CSV・Excel・PDF・JSON）を絶対に置かない。** GitHub Pages は公開URLで、履歴にも残る。
- アプリ本体は空。内線データは「データファイルを作る（管理用）」で AES-256-GCM（鍵は PBKDF2-SHA256・60万回）で暗号化した `ext-data.enc` にして配る。
- 取り込み方は2通り。
  - **ファイルを選ぶ**（推奨）：`ext-data.enc` を Dropbox やファイルアプリに置き、アプリの「ファイルを選ぶ」で取り込む。ネットに暗号文も出ない。
  - **ダウンロードして取り込む**：`ext/data.enc` を置いたときだけボタンが出る。暗号文が公開されるので、推測されない長いパスフレーズ（20文字以上の文）が前提。
- 取り込んだデータは端末の IndexedDB に暗号化したまま保存。「この端末で記憶する」を選ぶと、取り出せない形の鍵（non-extractable CryptoKey）を端末に保存し、次回からパスフレーズなしで開く。
- 更新：新しい `ext-data.enc` を作り、設定 →「新しいデータに更新」。パスフレーズを変えたときは各端末で取り込み直す。
- 端末を手放すときは 設定 →「この端末のデータを全部消す」。
- 「入力クリア」は検索語だけを消す。内線データ・お気に入りは残る。

## 共通基盤（2026-11-14〜）
- **患者プロファイル（profile.js）**：localStorage `ward-profile` に `{v:1, age, sex, weight, renal, liver, preg, at, updatedAt}`。氏名・IDは入れない。同じ端末・同じブラウザ（同じホーム画面アプリ）内の全アプリで共有。
  - 値：age `lt65`/`65-74`/`ge75`、sex `m`/`f`、weight 数値、renal `ge60`/`30-59`/`15-29`/`lt15`（15未満・透析）、liver `normal`/`cpB`/`cpC`、preg `none`/`preg`/`lact`、at `none`/`ap`/`ac`/`both`。未設定は null。
  - API：`WardProfile.get()`／`set({...})`（null で全消去）／`onChange(fn)`／`clear()`／`open()`／`label()`／`isStale()`。
  - data属性：`data-wp="項目" data-wp-v="コード[,コード]"`（radio・checkbox・option・ボタン）、`<select data-wp>`、`<input data-wp="weight">`、`data-wp-show="項目:コード"`、`data-wp-ro`（書き戻さない）、`data-wp-host`（帯を置く場所）。詳しくは profile.js 冒頭のコメント。
  - 入力クリア（wc-clear）の確認ダイアログに「患者プロファイルも消す」が自動で付く（wc-clear ブロック自体の変更は不要）。
- **結果の固定表示（wc-sum）**：`blocks/wc-sum.html` を貼る。`.verdict` など画面に見えている最初の要素の要約（`.big` と `.pill`）をヘッダー下に表示し、入力のたびに更新。タップで元の場所へ。アプリから `wcSum.set("文",{tone:"crit",pill:"レッド"})` でも指定できる。
- **入口**：検索（名前・キーワード。キーワードは index.html の KW か li の data-kw）、☆お気に入り（`ward-fav`）、よく使う＝最近開いた5件（`ward-recent`、share.js が各アプリを開いたときに記録）。
- 連動済み：aed（性別・体重・Child-Pugh・妊娠）、atn（体重・性別・抗凝固薬）、htn（年齢・性別・腎機能・妊娠）、lipid（性別・年齢区分・腎機能・肝機能・妊娠授乳・抗凝固薬。年齢の数値・eGFRを入れると区分を書き戻す。結果は wc-sum に固定表示）。、inf（性別・体重・腎機能〈CrClを計算すると区分を書き戻す。Crが無いときは区分だけで表17Aの該当行を出し、区分内で分かれる薬は両方表示〉。妊娠授乳・Child-Pugh B/C は表8A・18A未収載の注意を表示。起因菌不明フローの推奨を wc-sum に固定表示）
